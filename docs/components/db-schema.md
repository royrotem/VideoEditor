# Component: DB Schema

> The relational schema that backs every editing project: assets, chat
> sessions, EDL versions, and render jobs.

## Purpose

Persist the durable state of the application. Each table maps 1:1 to a
domain concept, so the schema stays readable without any extra
ORM-aware tooling.

## Tables

| Table          | Purpose                                                              |
| -------------- | -------------------------------------------------------------------- |
| `projects`     | One editing project per user-uploaded video idea                     |
| `assets`       | Raw uploaded files (video / audio / image) attached to a project     |
| `sessions`     | Chat sessions between the user and the agent network                 |
| `messages`     | One row per turn inside a session                                    |
| `edl_versions` | Immutable versioned snapshots of the Edit Decision List              |
| `render_jobs`  | One row per attempt to render an `edl_version` into a video          |

```
projects ──┬─< assets
           ├─< sessions ──< messages
           ├─< edl_versions  >── (optional) sessions
           └─< render_jobs  >── edl_versions
```

## Conventions

- **Primary keys**: UUIDv4, generated client-side at insert time.
- **Timestamps**: `created_at` / `updated_at` are `timestamptz`,
  defaulted to `now()`, with `updated_at` bumped via SQLAlchemy
  `onupdate`.
- **Enums**: declared in `app.db.enums` as `StrEnum`, materialised in
  Postgres as native `ENUM` types (`asset_status`, `session_status`,
  `message_role`, `job_status`).
- **Naming**: indexes / constraints follow the convention in
  `app.db.base.NAMING_CONVENTION` so Alembic autogenerated diffs are
  stable.
- **Cascades**: deleting a `project` removes everything below it;
  deleting a `session` nulls the `edl_versions.session_id` reference but
  keeps the EDL row (the EDL outlives its originating session).

## Public interface

The ORM models in `backend/app/db/models.py` are the single source of
truth - any other module should import the model classes rather than
issuing raw SQL.

## Inputs / outputs

Models are consumed via SQLAlchemy `AsyncSession`. The session
dependency lives at `app.db.session.get_db_session`.

## Dependencies

- SQLAlchemy 2 (`AsyncSession`, declarative).
- PostgreSQL 16 (uses `JSONB` and native enums).
- Alembic (migrations live in `backend/alembic/versions`).

## Errors

Standard SQLAlchemy errors propagate. Routes should translate
`sqlalchemy.exc.IntegrityError` into domain errors at the API layer.

## How to test

- Static / metadata: `backend/tests/test_models.py`.
- Integration (requires the docker-compose Postgres): coming alongside
  the asset-upload feature.

## Change log notes

- `edl_versions` is **append-only** by design - never `UPDATE` an
  existing row, always insert a new version. This keeps the editing
  history reproducible.
- `render_jobs.status` is the only place where job lifecycle is
  authoritatively recorded; Celery state is not relied on as a source
  of truth.
